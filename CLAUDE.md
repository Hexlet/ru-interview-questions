# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Сборник вопросов с реальных собеседований от Хекслет.Карьеры. Это content-only репозиторий:
только Markdown на русском, никакого кода, сборки, тестов и CI.

**Главное правило: вопросы не придумываются.** В репозиторий попадают только вопросы, которые
реально задавали на собеседованиях. Нельзя генерировать, дописывать «по смыслу» или добивать
тонкий раздел синтетическими вопросами — если раздел выглядит пустым, надо сказать об этом,
а не заполнять его.

## Lint

```sh
rumdl check .          # проверить все файлы (конфиг — .rumdl.toml)
rumdl fmt              # автофикс
```

Осторожно с «починкой линтера»: почти все ~4000 замечаний — это MD013 (длина строки > 80)
на строках-вопросах и на абзацах ответов. Это ожидаемо: ни вопросы, ни ответы не переносят
по 80 колонок, и MD013 в конфиге намеренно оставлен включённым. Ещё ~10 — MD041 (нет h1)
в файлах `common/`, `softskills/` и в README, где его исторически нет, плюс единичные MD036,
MD064 и MD077 в старых файлах. MD033 (inline HTML) выключен в `.rumdl.toml`, потому что
ответы оформлены раскрывашками `<details>`/`<summary>`.

Правь только то, что относится к твоим изменениям; `rumdl fmt` без аргументов переписывает
все Markdown-файлы репозитория, а не только тот, который ты трогал.

## Структура и соглашения

Три уровня файлов в `questions/`:

- `questions/<role>.md` — вопросы по направлению (frontend, java, php, devops, …).
  Формат: h1 с названием → список кросс-ссылок на общие файлы → `## Junior` / `## Middle` →
  внутри `### <тема>` (Общие вопросы, Docker, Безопасность и т.п.).
- `questions/common/*.md` — общие темы (algorithms, networks, databases, metodologies,
  softskills), на которые ссылаются файлы направлений. Обычно без h1, сразу `##`.
- `questions/softskills/<role>.md` — софт-скиллы по направлению в другом формате:
  сначала список оцениваемых компетенций, затем `## Вопросы по ключевым компетенциям`
  и `### <компетенция>`, где перед вопросами идут курсивные блоки `_Цель:_` / `_Как отвечать:_`.

Два разных места для софт-скиллов, легко положить не туда:
`questions/common/softskills.md` — общий список, на него ссылаются файлы направлений;
`questions/softskills/<role>.md` — разбор по компетенциям для конкретного направления,
на него ссылается README.

Ответы к вопросам лежат прямо под вопросом в раскрывашке и добавляются **только вставками**,
без правки самой формулировки вопроса:

```markdown
1. Что такое замыкание? Приведи пример.
   <details>
   <summary>Ответ</summary>

   Замыкание — функция вместе с областью видимости, в которой она была создана: ...

   </details>
```

Отступ блока равен ширине маркера списка вместе с пробелом (для `1.` — 3 пробела, для `*`
и `-` — 2), внутри — обычный Markdown: абзацы, списки, код, ASCII-схемы. Абзац пишется одной
строкой и не переносится по 80 колонок. В файлах `softskills/` и в `common/softskills.md`
у раскрывашки другой заголовок — `Как отвечать`, потому что там разбирается не факт,
а стратегия ответа.

Прочие соглашения:

- `README.md` — единственный индекс. Каждый новый файл вопросов должен быть в него добавлен.
- Ссылки: внутри файлов вопросов — абсолютные от корня (`/questions/common/networks.md`),
  в README — относительные (`./questions/frontend.md`).
- Маркеры списков в файлах разные (`-`, `*`, `1.`) — следуй тому файлу, который правишь,
  не унифицируй заодно. Вложенность — 4 пробела (MD007, `.editorconfig`).
- Вопросы формулируются так, как их произносит интервьюер: на «ты», разговорно,
  часто несколько связанных вопросов одной строкой.
